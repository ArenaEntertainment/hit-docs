Private trading endpoints use API key HMAC authentication. Public market data endpoints do not require credentials.

For implementation examples in TypeScript, Python and Rust, see [Developer Authentication](/developers/authentication).

## REST Headers

Include these headers on private REST requests:

| Header | Type | Required | Description |
| --- | --- | --- | --- |
| `hit-api-key` | string | Yes | API key identifier. |
| `hit-signature` | string | Yes | HMAC-SHA256 signature. |
| `hit-timestamp` | string | Yes | Unix timestamp in milliseconds. |
| `hit-passphrase` | string | Yes | API passphrase. |

Signature message:

```text
timestamp + "\n" + method + "\n" + pathWithQuery + "\n" + body
```

Rules:

| Rule | Description |
| --- | --- |
| separator | One newline character (`\n`) between each part, with none after `body`. |
| `method` | Uppercase HTTP method, such as `GET`, `POST` or `DELETE`. |
| `pathWithQuery` | Full API path including `/api/v1` and the query string exactly as sent, excluding scheme and host. |
| `body` | The request body exactly as sent, byte for byte, or an empty string for no body. |
| timestamp window | Requests must be within 30 seconds of server time. |

The legacy message, `timestamp + method + path + body` concatenated with no separator and with the query string excluded from `path`, is still accepted. See [Developer Authentication](/developers/authentication) for how the two forms differ, a worked example, and the requests that accept only the legacy message.

A REST request whose **trading API key** fails authentication returns `401` with the message `Authentication failed`, whatever check failed.

A request whose key could not be checked, because the auth service could not be asked about it, returns `503` instead. Its body's `error` is `CREDENTIAL_UNVERIFIABLE` and its `message` is `Service Unavailable`, and it carries no `Retry-After` header. It says nothing about whether your key is valid: re-send the request, signed again with a fresh `hit-timestamp`, and do not deactivate or replace the key because of it. It can come from any endpoint that verifies a key, including `GET /markets`, `GET /markets/{id_or_slug}`, `GET /markets/{id_or_slug}/users`, `GET /markets/{id_or_slug}/holders` and `GET /markets/activity`, which verify the key when you send `hit-api-key` and refuse a failing one with the `401` above.

When you present a JWT instead:

| Endpoint | JWT fails verification | JWT could not be verified |
| --- | --- | --- |
| Requires a JWT, or accepts one in place of an API key | `401` | `503` with `error: CREDENTIAL_UNVERIFIABLE`, as above |
| `GET /markets`, `GET /markets/{id_or_slug}`, `GET /markets/{id_or_slug}/users`, `GET /markets/{id_or_slug}/holders`, `GET /markets/activity` (without `hit-api-key`), `GET /markets/activity/{marketId}`, `GET /leaderboards`, `GET /rewards/leaderboard` | `403` | `403` |
| `GET /events`, `GET /events/{id_or_slug}`, `GET /events/{id_or_slug}/volume`, `GET /events/{id}/positions` | Answered as a request with no credential | Answered as a request with no credential |

## WebSocket Auth Payload

Authenticate the `/user` namespace by emitting `user-connect` after connecting.

Payload type: `TradingApiKeyAuth`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `apiKey` | string | Yes | API key identifier. |
| `signature` | string | Yes | HMAC-SHA256 signature. |
| `timestamp` | string | Yes | Unix timestamp in milliseconds. |
| `passphrase` | string | Yes | API passphrase. |

Signature message:

```text
timestamp + WEBSOCKET + /user
```

The newline-separated REST message is not accepted for this handshake.

Authentication result event: `user-authenticated`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `success` | boolean | Yes | Whether authentication succeeded. |
| `error` | string | No | Failure reason. |
