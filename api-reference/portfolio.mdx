## Get User Positions

```text
GET /api/v1/markets/user-positions
```

**Authentication:** `API key HMAC`

Query parameters:

| Query | Type | Required | Description |
| --- | --- | --- | --- |
| `status` | enum string | No | Market status: `DRAFT`, `ACTIVE` or `RESOLVED`. |
| `id` | UUID string | No | Market UUID. |
| `eventId` | UUID string | No | Event UUID. |
| `title` | string | No | Case-insensitive title filter. |
| `page` | integer | No | Page number. Default `1`. |
| `limit` | integer | No | Results per page. Default `10`. |
| `sortBy` | enum string | No | `latest`, `current`, `initial` or `return`. Default `latest`. |
| `order` | enum string | No | `ASC` or `DESC`. Default `DESC`. |

Response type: `UserPositionsResponse`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `first` | integer | Yes | One-based index of the first item on the current page. |
| `last` | integer | Yes | One-based index of the last item on the current page. |
| `limit` | integer | Yes | Results per page. |
| `total` | integer | Yes | Total matching positions. |
| `data` | `UserPosition[]` | Yes | User positions. |

When Hit cannot read the markets of your positions because of a fault on its side, this endpoint answers `500` with `message: "Internal server error"`, or `503` with a `Retry-After: 1` header when the server's database connections are all in use. Re-send a `503` after the wait the header gives; a `500` is a server fault, not a problem with your request. See [Server Error Changes](/api-reference/server-error-changes).

## Neg-Risk Position Actions

These four routes act on your positions in a neg-risk event. Each one submits a single transaction from your wallet and answers `201` with `{ "txHash": "0x..." }`. The routes are on `/wallet`, not `/markets`.

**Authentication:** `API key HMAC`

Common behaviour:

- `amount` is a positive integer string in raw units, with no leading zeros, at most 78 digits and no larger than the uint256 maximum. It is the amount of each outcome token the action moves; the USDC figures, where there are any, are under each route.
- A body with a malformed field, or with a property the route does not declare, is refused with a generic `400` that has no `code`.
- A wallet with no address is refused before anything is read or signed.
- An `eventId` that is not a neg-risk event Hit can act on is refused with `400` and no `code`: for example one Hit's records do not fully match on chain, or one whose every market has been reported NO. So is a `marketIds` entry on `convert-positions` that is not a prepared neg-risk question.
- A `400` with `errorCode: "wallet-code-changed"` (an `errorCode`, not a `code`) means your wallet's code is no longer the one Hit set up. It is the same answer that [order admission](/api-reference/orders#admission-errors) gives.
- A `400` with `message: "Signature required. Session signer not granted."` or `"Signature required. No Privy account found."` means Hit has no permission to sign for your wallet. A `422` `not_broadcast` body does not name its cause, and one that repeats when you resend can mean the session signer is not granted. Sending the request again does not clear that until the wallet is connected in the app again.
- Insufficient token holdings are refused with `400` before anything is signed.

Refusals every route can return:

| Status | `code` | Meaning | What to do |
| --- | --- | --- | --- |
| `400` | `would_revert` | The simulation of the action reverted, so nothing was sent. | Sending the same request again normally fails the same way. |
| `409` | `outcome_unknown` | The transaction may have been sent and may still go through. The answer carries no transaction hash. | Check your positions before sending the request again. |
| `409` | `in_flight` | Another action for your wallet, or a redemption that may still land, is in progress. Nothing was sent. | The pending transaction may be this same request, sent earlier. Check its result, or your positions, before deciding whether to send the request again. |
| `422` | `not_broadcast` | The action was refused before the send, for a reason with no code of its own. Nothing was sent. | The same request can be sent again. The body does not name the cause; if it repeats, see the session signer note above. |
| `422` | `too_large_for_one_transaction` | The action needs more gas than one transaction may use. Nothing was sent. | The same request is refused again. |
| `503` | `yes_set_chain_unavailable` | The chain state the action depends on could not be read. Nothing was signed or sent. | The request can be sent again. It carries no `Retry-After`. |

The refusals listed under each route are in addition to these.

### Convert Positions

```text
POST /api/v1/wallet/convert-positions
```

**Authentication:** `API key HMAC`

Converts your NO positions in one or more markets of one neg-risk event. The markets must all belong to the same neg-risk event, and you must hold at least `amount` of the NO token of every selected market. You receive `(marketIds.length - 1) * amount` USDC and `amount` of the YES token of every other market of the event, including markets flagged `hidden`. With one market you receive no USDC.

Request body:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `marketIds` | UUID string[] | Yes | Distinct market UUIDs whose NO positions are converted. Minimum `1`, maximum `256`. |
| `amount` | string | Yes | Positive amount of each selected NO token, in raw integer units. |

Request example:

```json
{
  "marketIds": [
    "0b6a8f3e-5d52-4b3c-9d3a-6f0c2e1a7b11",
    "7c1d9e24-83a0-4f6e-b5a2-1d4e8c3f9a02"
  ],
  "amount": "1000000"
}
```

Response type: `{ txHash: string }`.

This route has no refusals of its own beyond the common ones and the `400` for an invalid selection: a market that does not exist, markets that do not belong to one neg-risk event, or less than `amount` held of a selected NO token.

### Merge YES Set

```text
POST /api/v1/wallet/merge-yes-set
```

**Authentication:** `API key HMAC`

Merges `amount` of every YES token of a neg-risk event that has not been reported NO, including markets flagged `hidden`, back into USDC, which returns `amount` USDC. You must hold at least `amount` of each of those YES tokens.

Request body:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `eventId` | UUID string | Yes | The neg-risk event whose YES set is merged. |
| `amount` | string | Yes | Positive amount of each token in the set, in raw integer units. |

Request example:

```json
{
  "eventId": "3f2b7a90-1c4e-4d8b-a6f5-9e0d2c7b4a13",
  "amount": "1000000"
}
```

Response type: `{ txHash: string }`.

Refusals specific to this route:

| Status | `code` | Meaning |
| --- | --- | --- |
| `400` | `yes_set_actions_disabled` | The YES-set actions are switched off. |

### Split YES Set

```text
POST /api/v1/wallet/split-yes-set
```

**Authentication:** `API key HMAC`

Splits `amount` of USDC into `amount` of every YES token of a neg-risk event that has not been reported NO, including markets flagged `hidden`. Your wallet must hold at least `amount` of USDC.

Request body:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `eventId` | UUID string | Yes | The neg-risk event whose YES set the USDC is split into. |
| `amount` | string | Yes | Positive amount of each token in the set, in raw integer units. |

Request example:

```json
{
  "eventId": "3f2b7a90-1c4e-4d8b-a6f5-9e0d2c7b4a13",
  "amount": "1000000"
}
```

Response type: `{ txHash: string }`.

Refusals specific to this route:

| Status | `code` | Meaning |
| --- | --- | --- |
| `400` | `yes_set_actions_disabled` | The YES-set actions are switched off. |
| `400` | `insufficient_usdc` | Your wallet holds less USDC than `amount`. |
| `503` | `usdc_unavailable` | Your USDC balance could not be read. Nothing was signed or sent, so the request can be sent again. It carries no `Retry-After`. |

### Convert YES to NO

```text
POST /api/v1/wallet/convert-yes-to-no
```

**Authentication:** `API key HMAC`

Turns the YES positions you hold in a neg-risk event into NO positions of the markets you choose. With one target, your YES set becomes NO of that market. With several targets, the action also spends USDC. Your wallet must hold `targetMarketIds.length * amount` of USDC, which is also what Hit approves, and the net USDC spent is `(targetMarketIds.length - 1) * amount`, so one target spends none, net. The YES set is every market of the event not reported NO, including markets flagged `hidden`. You must hold at least `amount` of the YES token of every market in the YES set that is not a target, and the targets must be fewer than the markets in the YES set.

Request body:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `eventId` | UUID string | Yes | The neg-risk event holding the positions. |
| `targetMarketIds` | UUID string[] | Yes | Distinct UUIDs of open markets of the event whose NO positions you receive. At least `1`, at most `40`. |
| `amount` | string | Yes | Positive amount of each token, in raw integer units. |

Request example:

```json
{
  "eventId": "3f2b7a90-1c4e-4d8b-a6f5-9e0d2c7b4a13",
  "targetMarketIds": ["0b6a8f3e-5d52-4b3c-9d3a-6f0c2e1a7b11"],
  "amount": "1000000"
}
```

Response type: `{ txHash: string }`.

Refusals specific to this route:

| Status | `code` | Meaning |
| --- | --- | --- |
| `400` | `yes_set_actions_disabled` | The YES-set actions are switched off. |
| `400` | `insufficient_usdc` | Your wallet holds less USDC than `targetMarketIds.length * amount`. |
| `400` | `convert_targets_too_many` | More than `40` targets. |
| `400` | `invalid_convert_target` | A target is not an open market of the event, was already reported, is repeated, or the targets are every market in the YES set. |
| `400` | `event_determined` | The event has a reported winner, so there is nothing to convert into. |
| `503` | `usdc_unavailable` | Your USDC balance could not be read. Nothing was signed or sent, so the request can be sent again. It carries no `Retry-After`. |

## UserPosition

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `market_uuid` | UUID string | Yes | Market UUID. |
| `tokenId` | string | Yes | Held outcome token ID. |
| `acquisitionPrice` | string | Yes | Average acquisition price. `"0"` when no purchase is recorded for the position, for example shares received from another wallet. Where the position holds more than was bought, the average of the bought shares only. |
| `amount` | string | Yes | Token amount held. |
| `latest` | string | Yes | Latest token price. |
| `current` | string | Yes | Current position value. |
| `initial` | string | Yes | Initial position value: `acquisitionPrice` × `amount`. `"0"` when no purchase is recorded for the position, which means unknown, not measured. Shares held beyond those bought are valued at the bought average. |
| `return` | string or null | Yes | Position return, as a percentage. `null` when the position's booked cost is zero, negative or missing, as for a position with no recorded purchase. |
| `icon` | string | No | Market icon URL. |
| `slug` | string | No | Market slug. |
| `title` | string | No | Market title. |
| `displayName` | string or null | Yes | Optional market presentation label. Use `title` when this is `null`. |
| `eventId` | UUID string | No | Parent event UUID. |
| `eventName` | string | No | Parent event name. |
| `eventIcon` | string | No | Parent event icon URL. |
| `isMultiMarket` | boolean | No | Whether the position belongs to a multi-market event. |
| `isSeriesLayout` | boolean | No | Whether the parent event uses the daily-series layout. |
| `status` | enum string | No | `DRAFT`, `ACTIVE` or `RESOLVED`. |
| `conditionId` | string | No | Conditional Tokens condition ID. |
| `resolvedTo` | string or number | No | Resolution outcome. |
| `outcome` | string | No | Outcome label. |
| `outcomeIndex` | integer | No | Outcome index: `0` or `1`. |
| `orderFeeRateBps` | integer | No | Market fee rate in basis points. |
| `passiveOrderFeeRateBps` | integer | No | Passive-order fee rate in basis points. |
| `proposedResolvedTo` | string | No | Proposed winning outcome: `YES`, `NO` or `TIE`. |
| `proposedAt` | integer | No | Current proposal time in Unix seconds. |
| `liveness` | integer | No | Dispute-window duration in seconds. |
| `isDisputed` | boolean | No | Whether the current proposal is disputed. |
| `isSettled` | boolean | No | Whether the oracle has settled the market before final platform resolution. |

`proposedResolvedTo` and `proposedAt` describe the current proposal and can remain present after final resolution. Use `status !== "RESOLVED"` when deciding whether to show a pending-resolution state.
